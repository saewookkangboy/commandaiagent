# 비공개 Google Sheets 문의 운영

## 저장 구조와 공개 경계

웹사이트 `/consulting` → 동일 출처 `/api/lead` Vercel Node 함수 → HMAC 서명 검증 Apps Script 웹앱 → 소유자 비공개 스프레드시트의 `문의접수` 탭입니다. 시트는 링크 공개하지 않습니다. 코드에는 시트 ID·실제 서명 비밀이 없으며, Vercel 환경과 Apps Script ScriptProperties에만 설정합니다. 기존 Workspace 연결을 사용하며 새 DB·메일 서비스는 사용하지 않습니다.

- Vercel 환경: `SHEETS_WEBAPP_URL`, `SHEETS_SIGNING_SECRET` (Production에만 설정. 브라우저용 접두사 사용 금지)
- Apps Script: `SHEET_ID`, `SIGNING_SECRET`; 소유자 계정만 초기 설정 가능합니다.
- `content/funnel.json`의 `policy_approved`와 서버 설정이 모두 준비되어야 접수합니다. 미설정·오류에는 이메일 대체 경로를 유지합니다.
- 웹앱은 소유자 실행이며 익명 POST를 받되 서명·타임스탬프가 없으면 기록하지 않습니다. 문의 조회/내보내기 API는 제공하지 않습니다. Google 최초 OAuth 승인은 운영자 본인이 진행해야 합니다.

## 시트 열

접수시각(KST), 접수ID, 문의유형, 관심업무, 회신이메일, 소속, 메모, 유입글, CTA, UI버전, 동의문버전, 처리상태, 중복검증해시 — 총 13개입니다.

회신이메일·문의유형·관심업무가 필수이며, 소속·메모는 선택입니다. 접수시각과 동의문 버전은 저장 시 함께 남깁니다. 분석 도구에 입력 원문을 보내지 않습니다. 원문 IP와 요청 제한용 일별 해시 값은 시트 열에 저장하지 않습니다. 접수 ID는 중복 방지를 위한 식별자이며 개인정보와 결합된 시트 자체를 비공개로 관리해야 합니다.

## 운영자 처리

1. 시트의 `처리상태`가 `신규`인 문의를 확인합니다.
2. 입력된 회신 주소로 답변하고 상태를 `확인 중`, `회신 완료` 등으로 갱신합니다. 답변 기한이나 계약·서비스 제공을 자동 확정하지 않습니다.
3. 자동 접수 확인 메일·뉴스레터·광고 발송은 구현하지 않았습니다. 방문자에게도 동일하게 안내합니다.
4. **문의 처리 완료 후 지체 없이 파기하며, 접수일부터 최대 3개월**을 넘기지 않는 기준을 운영자가 수동으로 적용합니다. 법령상 보관 의무는 예외입니다. 자동 삭제 작업은 설정하지 않았습니다. 정기 자동 삭제가 필요하면 대상·보존 예외·승인·복구 기준을 별도로 정해야 합니다.
5. 고객의 열람·정정·삭제 요청은 `chunghyo@troe.kr`에서 접수합니다. 담당자 외 시트 공유를 추가하려면 별도 승인이 필요합니다.
6. 예시·테스트 행은 `[TEST]`임을 명시해 실제 문의와 구분합니다. 테스트만을 이유로 기존 실문의 행을 삭제하지 않습니다.

## 오류와 중복

- Google Sheets 저장/flush 확인 후에만 성공 응답 → `문의가 저장되었습니다`와 `lead_form_success` 발화입니다.
- 응답 유실 시 브라우저에 입력값을 유지합니다. 같은 화면에서 재시도하면 같은 접수ID를 사용하며, 동일 내용은 기존 저장 성공으로 처리합니다.
- 같은 ID에 다른 내용을 보내면 충돌 오류입니다. 내용을 바꾸고 재시도할 때는 새 ID가 생성됩니다. 페이지를 새로고침하면 입력값과 요청ID를 복구하지 않습니다. 개인정보를 브라우저 저장소에 넣지 않기 위한 경계입니다.
- 서버·네트워크 오류·요청 제한은 완료로 계산하지 않습니다. 이메일 대체 연락 경로를 표시합니다.
- 허니팟·동일 출처·서버 HMAC·스크립트 잠금·수식 선행 문자 이스케이프와 기초 요청 제한을 적용했습니다. 완전한 스팸·DDoS 차단을 보장하지 않으며 대규모 트래픽에는 별도 운영 대책이 필요합니다.

## 검증

- `node scripts/check_lead_backend.cjs`: 네트워크 없는 Node/Apps Script 메모리 모형 검사. 비승인 차단·서명·저장확인 ID·중복/충돌·수식 이스케이프·오류·소유자 설정 보호.
- `python3 scripts/check_funnel.py`: 모든 운영 URL을 로컬 파일/가상 응답으로 대체해 폼·지연 CTA·이벤트 payload를 검사. 실제 분석·접수 서버 전송 없음.
- 실제 운영 연결은 배포 후 별도 `[TEST]` 접수와 시트 행을 대조해야 확인됩니다. 위 모형 검사는 실서비스 연결의 증거를 대신하지 않습니다.
