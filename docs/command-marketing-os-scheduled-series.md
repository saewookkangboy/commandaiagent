## 준비 상태와 공개 상태

`content/scheduled/command-marketing-os/`에 승인된 원고·메타데이터·이미지와 SHA-256 무결성 기록을 보관한다. Vercel의 공개 출력은 기존 `dist`이며 이 예약 원본을 정적 자산으로 복사하지 않는다. 아직 공개하지 않은 편은 `content/blog/posts.json`, 공통 계측 슬러그, 홈·블로그 목록·sitemap·llms·routes·상세 HTML·이미지에서 제외된다.

`python3 scripts/publish_scheduled.py`는 현재 한국시간으로 **당일** 슬롯과 `publish_at`을 확인한 뒤 한 편만 로컬 원고·목록·이미지·계측·사이트 갱신일에 승격한다. `--dry-run`은 읽기 전용이다. 실제 저장소에는 미래시각 주입 옵션이 없다. 이미 등록된 글은 중복 추가하지 않는다. 이전 편이 누락되면 후속 편만 공개하지 않고 중단한다. 날짜를 소급하거나 세 편을 즉시 공개하는 대체 동작은 하지 않는다.

신규 시리즈는 기존 책 소개3편과 별개이고 `series_key=command-marketing-os`, `kind=guide`다. 공개된 편만 실제 링크를 제공하며 미래 편은 제목·날짜와 ‘발행 예정’ 텍스트로 안내한다. 다음 편 공개 시 이전 편 내비게이션도 재생성하고 최초 게시일은 보존하며 수정일만 갱신한다. GA4/Meta는 기존 문맥의 `article_slug`, `content_id`, `series_order` 및 `practical_guide` 그룹을 쓴다.

## 예약 실행 지침

미래 실행은 로컬 파일이 남아 있다고 가정하지 않는다. 현재 연결 상태를 확인하고 GitHub CLI로 **기존** `saewookkangboy/commandaiagent` 최신 main을 가져온다. 폴더가 없으면 `gh repo clone saewookkangboy/commandaiagent`를 이용한다. 다른 저장소·호스팅·계정·광고·예산·워크플로 권한을 만들지 않는다. 빌드 의존성과 기존 브라우저 검사 환경을 확인한다.

1. 현재 한국시간·원격 main·운영 현황을 읽고 `publish_scheduled.py --dry-run`으로 당일 슬롯을 확인한다. 이미 발행됐으면 새 변경 없이 운영 상태만 확인한다. 권한이 없거나 이전 편이 누락되면 날짜별 발행 실패를 명확히 보고하며 임의로 다른 날짜 글을 대신 공개하지 않는다.
2. 최신 main에서 해당 날짜 전용 변경 브랜치를 만든다. `publish_scheduled.py`와 `build_blog.py`를 실행한다. `check_blog.py`, `check_cta.py`, `check_series_analytics.py`, `check_analytics.py`, `check_funnel.py`, `check_lead_backend.cjs`로 현재 공개분을 검사한다. 외부 분석 요청·문의 저장·구매는 하지 않는다.
3. 당일 원고·썸네일·메타·계측 허용 슬러그·사이트 갱신일과 생성 산출물만 커밋·푸시하고 PR을 만든다. 원격 main 변경과 PR 배포·보안·검토 결과를 확인해 안전하게 병합한다. 강제 푸시·기존 변경 삭제·중복 PR·GitHub Actions 신규 생성은 하지 않는다. GraphQL 인증 실패와 검사 실패를 혼동하지 말고 정상 REST 경로로 기존 PR 실제 상태부터 확인할 수 있다.
4. 병합된 최신 main과 작업 사본을 일치시킨 뒤 `verify_scheduled_production.py --wait-seconds 600 --output <비공개증거경로>`로 운영 확인을 한다. 당일 글·이전 편·홈·목록·sitemap·llms·공통 계측 설정·이미지는 main 출력과 바이트 일치, 미래 상세·이미지는404, 검색 봇6종 접근과 canonical·FAQ·CTA는 기존 검사로 확인한다. 임시 QA 데이터 수신 감사는 이 예약의 범위가 아니다.
5. 사용자에게 공개 글 URL과 검증 성공/실패를 간결히 보고한다. 미래 글은 아직 예약이라는 상태를 유지하고, 네이버/Google 색인·검색 유입·책 구매를 보장하지 않는다. 22일 이후 추가 발행하지 않으며 예약은 그날 종료 시각에 만료된다.

## 준비본 회귀 검사

`python3 scripts/check_scheduled.py --full`은 별도 임시 복사본에서 19일·20일08:59:59의 비공개, 각 날짜09시의 한 편 공개, 재실행·반복 빌드 멱등성, 이전 편 누락 차단, 미공개 링크·이미지·검색 문서 제외, FAQ 가시/스키마 일치, 책 CTA, 원래 게시일 보존, 오프라인 분석·퍼널·문의 검사를 수행한다. 실제 작업 저장소의 미래 공개분을 만들지 않는다. 이 준비본 전용 검사는 세 편 공개 전 상태를 기준으로 하므로 실제 발행 실행에서는 위의 공개분 검사를 사용한다.

## 예약 등록 상태 (준비 시점)

세 날짜 공개의 독립 사본 검사와 현재 운영의 미공개 상세·자산404 검증은 통과했다. 그러나 현재 작업의 기본 ScheduleTask 생성은 별도 관리 배포 상태 요건으로 거절됐고 등록되지 않았다. 운영 Vercel 사이트는 정상이며 새 사이트를 만들거나 배포 설정을 바꾸지 않는다. 대안으로 공식 `schedule.due` 이벤트의 세 `once` 타이머(2026-10-20·21·22T09:00:00+09:00)를 생성 없이 미리 검증했으며, 사용자에게 일회성 타이머 방식을 선택할지 요청했다. 선택·실제 생성 확인 전에는 ‘예약 완료’로 보고하지 않는다. 세 편의 실제 운영 공개도 미래 실행 결과로 각각 확인한다.
