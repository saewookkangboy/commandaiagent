# 『AI AGENT를 지휘하는 마케터』를 실제 실무에서 활용하는 방법

**『AI Agent를 지휘하는 마케터』 실무 활용의 출발점은 책에 나온 Agent를 한꺼번에 만드는 것이 아닙니다.** 반복 업무 하나를 골라 입력 자료, R-G-C-T-O-R 업무 지시서, 출력물 검수표와 수정 기록을 연결해 보세요. 책에서 읽은 원칙이 다음 캠페인에도 꺼내 쓰는 문서가 될 때, 독서가 실제 운영으로 이어집니다.

박충효의 책은 무엇을 맡길지 정하고, 필요한 맥락을 제공하며, 결과를 검수하는 운영 구조를 다룹니다.[1] 이 글은 도서의 원칙을 재서술하고 **가상의 B2B 콘텐츠 캠페인**에 적용한 Command Marketing 편집 가이드입니다. 책의 실제 고객사 사례나 저자가 직접 작성한 실행 매뉴얼을 옮긴 글은 아닙니다.

## 읽은 내용을 오늘의 산출물로 바꾸세요

책을 읽으며 좋은 문장만 표시하기보다 “이 부분을 읽고 우리 업무에 어떤 문서를 만들 것인가?”를 적어 보세요. Part 3의 지시서 구조에서는 업무 브리프를, Part 5의 콘텐츠 원칙에서는 아웃라인과 발행 전 검수표를, Part 6의 리포팅에서는 다음 행동을 정하는 회의 요약을 만들 수 있습니다. Part 7에서는 이 문서를 이름과 버전이 있는 재사용 카드로 정리합니다.

예를 들어 다음 주 비교 검토 단계의 고객에게 보여줄 블로그 글 하나가 필요하다면, 책 전체를 다시 요약하는 대신 해당 글의 목적과 입력 자료부터 적습니다. 도입 여부를 검토하는 독자에게 무엇을 설명해야 하는지, 읽은 뒤 어떤 판단이나 다음 행동을 도울 것인지 정하는 일입니다.

아직 Agent나 자동화 서비스가 없어도 팀이 허용한 AI 도구에서 지시서와 검수 흐름을 먼저 시험할 수 있습니다. 다만 이것은 업무 방식을 연습하는 것이지, 도구 접근 권한과 무인 자동 실행까지 구축한 상태는 아닙니다. Anthropic도 가능한 한 단순한 방식부터 시작하고, 고정된 단계로 처리할 수 있는 업무에는 예측 가능한 워크플로를 고려하라고 설명합니다.[2]

## 첫 업무는 입력과 완료 기준이 보이는 것으로 고르세요

처음에는 캠페인 전체보다 그 안의 작은 결과물 하나가 적합합니다. “콘텐츠 마케팅을 자동화한다”보다 “승인된 제품 자료와 익명화한 고객 질문으로 비교 가이드의 아웃라인을 만든다”가 시험하고 수정하기 쉽습니다.

선택한 업무에는 누가 결과물을 쓰는지, 어떤 자료가 필요한지, 무엇을 검수하면 사용할 수 있는지가 보여야 합니다. 입력 자료가 없거나 최종 승인자가 정해지지 않았다면 생성부터 시작하지 말고 그 빈칸을 먼저 채우세요. 맡길 역할은 [마케팅 AI 에이전트 17가지 역할과 독서 가이드](/blog/book-ai-agent-roles-reading-guide)에서 살펴볼 수 있습니다. 책의 팀 운영 원칙도 초안 작성·추천과 실행 확정 권한을 나누고, 외부 공개와 예산·발송처럼 영향이 큰 결정은 사람이 검수하도록 설명합니다.

기존 AI 도구의 한 번 요청과 사람이 확인하는 방식으로 충분하다면 그대로 시작해도 됩니다. Agent의 자율성을 늘리는 것은 반복 사용에서 추가 자료 탐색이나 도구 선택이 실제 병목으로 확인된 뒤 검토할 문제입니다.[2] 어떤 모델이나 도구를 많이 연결했는지보다, 사용할 수 있는 결과물이 안정적으로 나오는지를 먼저 봅니다.

## 편집 응용 예시: B2B 비교 가이드의 지시서 만들기

다음 예시는 **가상의 B2B 서비스가 비교 검토 단계의 고객을 위해 블로그 글 하나를 준비하는 상황**입니다. 제품·고객·성과 수치는 가정하지 않습니다. 먼저 공개 가능한 제품 설명, 사용 조건, 실제로 확인된 FAQ와 익명화한 고객 질문을 준비합니다. 자료마다 출처와 확인일을 적고, 근거가 없는 기능·후기·절감 효과는 입력 목록에서 제외합니다.

책의 R-G-C-T-O-R은 Role·Goal·Context·Tool·Output·Review로 업무의 경계를 정하는 구조입니다. 이 구조를 적용한 다음 지시서를 복사한 뒤 대괄호 안을 자신의 업무에 맞게 채워 보세요. 빈칸을 채우기 위해 고객 개인정보나 회사 기밀을 입력할 필요는 없습니다.

```text
[편집 응용 지시서: B2B 비교 가이드 아웃라인 v1]

Role
당신은 비교 검토 단계의 고객 질문을 정리하는 콘텐츠 기획 보조입니다.
제품 기능·가격·성과를 확정하거나 외부에 게시하지 않습니다.

Goal
독자가 [해결하려는 문제]에 대해 우리 서비스의 적합성과 한계를
판단할 수 있는 블로그 아웃라인을 만듭니다. 신청을 강요하지 않습니다.

Context
독자: [담당 역할과 현재 검토 단계]
핵심 질문: [익명화하고 사용이 허용된 고객 질문]
브랜드 기준: [말투·표현·금지 문구]
다음 행동: [공개 점검표 확인 또는 적용 범위 문의]

Tool
이번 작업에서는 제공된 승인 자료만 사용합니다.
자료: [제품 설명·사용 조건·FAQ·출처와 확인일]
자료에 없는 사실은 만들지 말고 추가 확인 필요로 표시합니다.

Output
제목 후보, 검색 의도, 독자 질문, 섹션별 주장과 필요한 근거,
FAQ, 내부 링크 후보, 자연스러운 CTA를 포함한 아웃라인을 작성합니다.
아직 본문을 쓰지 말고 누락 자료와 사람의 결정이 필요한 항목을 끝에 적습니다.

Review
독자 질문에 답하는지, 근거와 가정이 구분되는지 확인합니다.
가격·기능·비교·후기·성과 표현은 승인 자료와 대조해야 합니다.
개인정보·보장 표현·자료에 없는 수치가 있으면 표시합니다.
사람이 아웃라인을 승인한 뒤에만 다음 작업으로 넘어갑니다.
```

이 지시서에서 Tool은 실제 연결된 서비스의 목록이라고 가정하지 않습니다. 제공 자료만 활용하도록 범위를 정한 것입니다. 외부 검색이나 사내 시스템 조회를 추가하려면 별도로 사용 권한, 허용 자료와 확인 방법을 정해야 합니다.

첫 산출물은 완성 원고가 아니라 아웃라인입니다. 책은 검색 의도·독자 질문·근거·CTA를 먼저 확인하고 방향을 승인한 뒤 초안을 작성하도록 설명합니다. “기능 비교 근거가 부족하다”는 결과가 나오면 자료를 보강하거나 해당 주장을 빼는 것이 다음 행동입니다. 자연스럽게 써 달라고 다시 요청해서 빈 근거를 덮지 마세요.

## 아웃라인 승인과 초안 검수를 다른 단계로 나누세요

아웃라인에서는 글의 방향을 확인합니다. 독자가 찾는 질문이 빠졌는지, 각 섹션이 같은 말을 반복하는지, 주장에 필요한 근거가 있는지, CTA가 현재 검토 단계에 맞는지를 봅니다. 방향이 틀렸다면 긴 초안을 만든 뒤 고치기보다 이 단계에서 수정하는 편이 낫습니다.

방향을 승인한 뒤에는 확정된 아웃라인과 승인 자료로 초안을 요청합니다. 이때도 근거가 없는 문장을 유려하게 완성하지 말고 확인 필요 표시를 유지하도록 합니다. 사람이 검증 가능한 브랜드 경험과 실제 설명을 보강하되, 경험이 없다면 만들어 넣지 않습니다.

초안 검수에서는 문장이 아니라 사용 가능성을 판단합니다. 책의 SEO QA는 검색 의도, 구체성, 전문성, 신뢰성, 전환 연결과 AI 문체를 함께 봅니다. 실제 실무에서는 제품 기능과 가격 조건을 원자료와 대조하고, 비교 표현·이미지 사용 권한·개인정보와 광고 표현에 필요한 담당자의 검토를 연결해야 합니다.

팀 메모에는 “조금 더 자연스럽게”보다 “두 번째 섹션의 비교 주장에 출처 없음”, “FAQ가 제품의 제외 조건을 빠뜨림”처럼 수정 이유를 적으세요. Agent가 다시 고칠 수 있는 피드백과 사람이 결정해야 하는 사항을 구분하는 데 도움이 됩니다. 생성·확인·후속 작성으로 작업을 나누는 방식은 Anthropic이 소개하는 단계형 워크플로의 활용 예와도 맞습니다.[2]

## 다음 담당자에게 넘길 수 있어야 업무가 끝납니다

초안 파일만 저장했다면 아직 콘텐츠 업무가 완료된 것은 아닐 수 있습니다. 검수한 원고, 사용한 근거, 미해결 사항과 승인 상태를 함께 넘겨야 다음 담당자가 다시 조사하거나 승인을 추정하지 않고 일할 수 있습니다.

가상 캠페인의 인계 문서에는 최종 제목과 원고 위치, 사용한 자료의 출처·확인일, CTA 목적지, 확인이 필요한 문장, 승인 담당자와 승인 상태를 적습니다. 아직 검수하지 않은 가격 문구가 있다면 “발행 승인”으로 표시하지 않고 검토 대기로 남깁니다. 게시 요청이 아니라 초안 검토 요청이었다면 완료 기준도 초안 전달에 머물러야 합니다.

자동화에서는 승인 상태를 메모만 해 두는 것과 실제 실행을 차단하는 것이 다릅니다. 게시·발송·예산 변경을 도구로 수행한다면, 승인과 접근 권한을 구현한 실행 단계가 별도로 필요합니다. 지시서에 “사람 승인 후 실행”이라고 적었다는 이유만으로 그 기능이 만들어지는 것은 아닙니다. 책 역시 외부 공개, 고객 데이터 활용과 예산 집행 등의 실행 확정 권한을 사람의 검수와 연결합니다.

## 성과 회고는 글 개수보다 사용성과 다음 판단을 보세요

첫 시험에서는 원고를 몇 개 만들었는지보다 자료를 다시 찾는 일이 줄었는지, 같은 오류를 반복하는지, 검수와 수정에 어떤 시간이 들었는지 기록하세요. 자료 준비, 지시서 작성, 사람의 검수·수정, 최종 정리에 쓴 작업 시간은 따로 적고 AI 생성 대기·승인 대기와 전체 경과 시간도 구분합니다. 특정 시간 절감률을 미리 목표 성과처럼 선언할 필요는 없습니다.

발행 후에는 검색 노출, 사이트 클릭, CTA 행동과 실제 저장된 문의를 다른 지표로 봅니다. 문의 버튼 클릭은 접수 완료가 아니며 접수 완료도 유효 문의나 매출과 같지 않습니다. 조회가 줄었다는 이유만으로 콘텐츠 품질이나 AI 사용이 원인이라고 단정하지 말고, 수집 오류·기간·시즌·표본·유입 경로와 실행 조건을 확인해야 합니다. 책의 리포트 원칙도 변화, 원인 가설, 다음 액션과 의사결정 요청을 구분하고 데이터·추적·인과관계의 한계를 표시하도록 설명합니다.

회고 결과는 다음 지시서에 반영합니다. “FAQ에 제외 조건 누락”이 반복되었다면 Context에 제외 조건 자료를 필수로 넣고 Review에 대조 항목을 추가합니다. 같은 지시서 이름 아래 v1.1처럼 버전을 붙이고 바꾼 문장, 이유와 검수 결과를 남깁니다. 책의 운영 매뉴얼은 프롬프트 카드, 입력값 체크리스트와 검수표를 실제 업무에 적용하고 버전과 다음 점검 기준을 축적하도록 설명합니다.

## 오늘 실행할 점검: 문서 네 개를 한 업무에 연결하세요

새 도구를 더 구독하기 전에 업무 지시서, 입력값 체크리스트, 출력물 검수표와 개선 기록을 같은 업무 이름으로 묶어 보세요. 처음부터 사내 시스템과 연결할 필요는 없습니다. 승인된 자료로 작은 시험을 한 뒤 재사용할 부분을 확인하면 됩니다.

- [ ] 이번 결과물을 쓰는 사람과 도울 판단을 적었다.
- [ ] 공개 가능하고 사용이 허용된 입력 자료, 출처와 확인일을 준비했다.
- [ ] R-G-C-T-O-R의 여섯 칸과 누락 자료 대응을 적었다.
- [ ] 아웃라인·초안·최종 사용의 검수와 승인 상태를 구분했다.
- [ ] 게시·발송·예산 변경은 적절한 담당자 승인과 실제 권한을 거친다.
- [ ] 사용한 결과물과 수정 이유를 다음 지시서 버전에 반영했다.

빈칸을 채울 때는 [R-G-C-T-O-R 공개 워크시트](/resources/rgctor-worksheet)를 사용할 수 있습니다. 책의 전체 구조는 [도서 목차](/#contents), 입력과 검수의 기본은 [책 소개 2](/blog/book-command-marketer-02), 반복 훈련과 기록은 [책 소개 3](/blog/book-command-marketer-03)에서 이어서 확인하세요. 이 실습을 21일 과정 전체와 동일한 절차로 해석할 필요는 없습니다.

## 자주 묻는 질문

### 책을 다 읽은 뒤에 실무 적용을 시작해야 하나요?

반드시 그럴 필요는 없습니다. 지금 맡은 업무에 맞는 파트를 읽고 작은 결과물 하나에 적용해 볼 수 있습니다. 다만 결과를 사용할 때는 거버넌스, 자료 사용과 사람의 승인 기준도 함께 확인해야 합니다.

### 코딩이나 Agent 구축 경험이 없어도 활용할 수 있나요?

네. 팀이 허용한 AI 도구에서 입력 자료와 업무 지시서, 검수표를 연결하는 연습부터 가능합니다. API·데이터 연결·자동 게시 같은 실행 기능은 별도 구성과 권한 관리가 필요합니다.

### 이 글의 B2B 캠페인 지시서가 책에 실린 원문인가요?

아닙니다. 책의 R-G-C-T-O-R과 검수 원칙을 활용해 새로 작성한 편집 응용 예시입니다. 실제 고객사 성과나 저자의 직접 집필 사례를 뜻하지 않습니다.

### AI가 검수했다고 표시하면 바로 발행해도 되나요?

아닙니다. AI의 자체 점검과 실제 사실·권한·브랜드·개인정보 검증은 다릅니다. 미해결 사항을 확인하고 담당자가 최종 사용을 승인해야 합니다. 법률·심의·개인정보의 전문 검토도 대체하지 않습니다.

### 첫 적용이 잘되지 않으면 Agent를 더 추가해야 하나요?

먼저 입력 자료, 목표, 산출물 형식과 검수 기준을 확인하세요. 같은 실패가 무엇인지 기록하고 지시서를 고친 뒤 다시 시험합니다. 복잡한 구조나 Agent 추가는 단순한 방식으로 해결되지 않는 문제가 확인되었을 때 검토할 선택입니다.

## 함께 읽을 내용과 적용 범위

박충효의 『AI Agent를 지휘하는 마케터』는 R-G-C-T-O-R 업무 지시서, 콘텐츠 기획·검수, 의사결정형 리포트와 재사용 가능한 운영 기록을 다룹니다. 이 글은 Part 3의 업무 지시서와 Workflow, Part 5의 고객 여정·SEO 아웃라인·QA, Part 6의 리포팅, Part 7의 권한·재사용·운영 기록이라는 주제를 B2B 콘텐츠 운영에 연결해 설명합니다.

가상 B2B 캠페인, 복사형 지시서, 인계 항목과 오늘의 점검은 **편집 응용**입니다. AI 초안을 활용한 Command Marketing 콘텐츠이며 저자가 직접 작성한 블로그 글은 아닙니다. 이 글은 도서 전체를 대체하지 않습니다. 실제 적용 시 조직의 정책, 사용 도구의 권한과 전문가 검토를 따라야 하며 업무 효율·검색 노출·AI 답변 인용·문의·매출을 보장하지 않습니다.
